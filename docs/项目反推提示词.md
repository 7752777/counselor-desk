# 辅导员工作台：项目反推提示词

> 兼容说明：本页保留早期总览，适合查看产品理念和基础约束。当前 v4.0 的桌面双端、文件资料库、手机交换、验收和发布提示词已拆分为 10 份纯文本文件，请从[AI 复现提示词归档](./prompt-archive.md)开始。

> 基于当前 `index.html`（v3.8.0）、数据约定和使用手册反推。用途是让 AI 重新生成一个同等定位、功能与交互质量的产品；它描述的是产品规格，不是原项目源码的逐行复刻。

## 使用方式

优先把“总提示词”完整交给具备代码执行能力的 AI。若模型单次输出有限，则先交付“基础约束”，再按“分阶段提示词”顺序继续；每一步均要求在已有代码基础上增量实现，不能删改已完成模块。涉及真实学生信息时，只能使用脱敏或示例数据。

## 总提示词

```text
你是一名资深前端工程师和高校学生工作产品设计师。请从零实现一个名为“辅导员工作台 / Counselor Desk”的可交付 Web 应用。它服务于一线高校辅导员的个人日常事务，不是学校正式的多人管理平台。核心价值是：打开即看到今天要处理的风险、回访、任务与截止事项；随手记下学生工作；月底能生成工作留痕。

一、交付与技术边界
1. 交付一个可直接双击运行的单文件 `index.html`，HTML、CSS、JavaScript 和 SVG 图标全部内嵌；核心功能零构建、零框架、零后端、零外部依赖、离线可用。
2. 数据仅保存于浏览器 localStorage，统一前缀 `cwb_v1_`，JSON 序列化；关闭页面不丢失。不得默认联网、上传或同步数据。CSV、JSON 导入导出必须离线可用；可选的 xls/xlsx 解析可按需加载，但离线时必须给出 CSV 替代方案。
3. 暴露 `window.CWB`：包含 `store`、`db`、`schema`、`norm`、`ui`、`hooks`、`bridge`、`modules.register(def)` 和 `consts`。写入数据前规范化，渲染用户输入前转义，避免 XSS。自定义模块注册后自动出现在导航中。
4. 首次打开写入可清空的、全量关联的脱敏示例数据，并以 `_demo:true` 标记；首页必须给出醒目的“当前展示示例数据”提示和清空入口。任何清空操作均二次确认。
5. 支持浅色/深色主题并持久化；支持键盘焦点、语义标签、焦点可见、`prefers-reduced-motion`；桌面优先且可在手机上查看、录入。不要做营销首页。

二、产品信息架构
左侧桌面导航按以下分组组织，手机端保留底部五个高频入口（今日、任务、学生、谈话、留痕），其余从抽屉进入：
- 工作台：今日概览、工作任务、学生台账、谈心谈话、工作留痕。
- 日常事务：校外住宿、假期去向、评优榜样、请销假、考勤台账、工作节点。
- 专项工作：学业预警、学业帮扶、奖助勤补。
- 重点关怀：重点学生档案、心理摸排、毕业生就业。
- 资源中心：政策智库、素材收藏、科创竞赛、模板库。
- 系统：平台联动与设置。
导航支持关键词筛选、分组折叠、常用模块置顶；顶部提供跨学生、任务、谈话、政策的全局搜索、主题切换和设置。

三、数据模型（每条记录都应有 id、created_at，允许 `_demo`）
1. students：student_number、full_name、gender、class_name、major_name、grade、college_name、counselor_name、enrollment_status、politics、phone、dorm、focus[]、focus_level(L1/L2/L3)、crisis_level、crisis_way、crisis_relieved、note。以学号去重；导入时空值不得覆盖已有信息。
2. tasks：title、duty、priority(P0/P1/P2)、source、classes、due、status(todo/doing/done)、note、platform_ref、done_at。逾期是 due 早于今天且未完成。
3. talks：date、student_number、student_name、way(面谈/电话/线上/家访/集体)、duty、summary、judge、action、need_follow、follow_date、done_follow。建立谈话要能从学生或首页预填学生。
4. stay、leave、honor：分别覆盖校外住宿/走读（审批、起止、紧急联系人）、假期去向（离返校、地址、家长同意、延迟）、评优榜样（申请类型、排名、德育、奖学金、社会工作、其他获奖）的完整台账字段。
5. pleave、attend、node：请销假（审批、销假）、考勤（日期、类型、节次、任课老师）、工作节点（职责、截止、提前提醒天数、重复周期、小结、附件说明）。
6. warn、help、grant：学业预警（红橙黄、课程、措施、跟进、解除）、帮扶（类型、帮扶人、周期、措施、效果、状态）、奖助勤补（类型、金额、批次、发放状态）。
7. focus、psych、graduate：重点学生档案（类别、一级/二级/三级、原因、措施、跟进、负责人、状态）、心理摸排（量表、得分、正常/轻中重度、建议、处理人、状态）、就业档案（毕业年份、就业状态、单位、岗位、地点、薪酬、签约）。
8. policy、material、comp、tpl：政策（分类、单位、文号、关键词、摘要、链接、收藏）、工作素材（分类、来源、标签、正文）、科创竞赛（类别、主办方、报名截止、学生、获奖）、模板库（通知/流程/表单、场景、正文）。
9. settings：辅导员姓名、学院、组织代码、主题、导航状态、置顶模块、示例数据与备份提醒状态、重点档案保护锁状态。

四、必须实现的业务联动
1. 首页“今天要处理”按严重度聚合并排序：未解除危机预警、重度未结案心理摸排、一级且到期未谈话的重点学生、红色未解除学业预警、待回访谈话、已过期未销假、到期/临期工作节点、14 天内或逾期赛事、逾期/今日/临近截止任务。每条给出最短路径操作，例如完成、顺延、回访、记新谈话、解除预警、建立帮扶、查看档案。
2. 关注等级对应谈话周期：L1 7 天、L2 14 天、L3 30 天；通过谈话的 student_number 或姓名计算最近谈话日期。
3. 首页必须有 KPI（逾期未办、在办任务、重点学生、未解除危机、本月谈话）、快速新建入口、近 6 个月谈话/任务趋势、九项辅导员职责工作量、学生关注结构及任务逾期率/谈话覆盖率等洞察。图表用内联 SVG，不引入图表库。
4. 九项职责作为所有任务、谈话、节点的统一分类：思政引领、党团班级、学风建设、日常事务、心理健康、网络思政、危机应对、就业指导、理论研究；使用稳定 key、名称和颜色映射。
5. 列表模块具备搜索、筛选、排序或视图切换、新建、编辑、删除、空状态；适合批量输入的模块提供 CSV 模板下载、CSV 导入、UTF-8 BOM CSV 导出。学生导入应支持常见中文表头同义词匹配、预览、按学号合并、缺失值容错。
6. 重点学生档案首次进入要求设置 4 位数字保护锁，查看时解锁、支持手动锁定；清楚说明这是防旁观的轻量保护，不是加密。一级且跟踪中的档案首页置顶。
7. “工作留痕”支持本月、本学期、自定义日期，汇总任务、谈话、风险、专项与职责分布，生成可编辑的结构化中文小结，可复制、下载 TXT、打印。文本只根据现有数据总结，不能编造事实。
8. “平台联动”可导出/导入完整 JSON 交换包；包包含 package、package_version、app_version、exported_at、counselor、scope、所有集合、custom 和统计。导入支持 merge（学生按 student_number、其余按 id）与 replace。还应提供“生成数据已内置的便携 HTML”功能。
9. 数据达到 30 条时温和提示备份。设置页提供导出完整备份、导入恢复、清空示例数据、清空全部数据和本地存储占用估算。

五、视觉与交互方向
1. 设计为“低空学院·工程版”：安静、密集、可靠的业务工具，而非大卡片营销页。浅色主背景 #eef2f8，上叠 24px 低对比工程蓝图网格；主品牌色深空航蓝 #0b3a82，信号青 #0bb4c4，警示琥珀 #e0a020，成功翠绿 #12a06b，危险红 #e0413e。深色模式需整套重配，不只是反色。
2. 采用系统中文字体栈。桌面侧栏约 256px，顶部栏约 60px，内容区最大宽度舒适、留白克制；基于 8px 间距体系。卡片白底、细边框、轻阴影、约 10-13px 圆角，KPI 卡片左侧 3px 工程色条；不要渐变大背景、装饰光球、巨型圆角卡片或套娃卡片。
3. 表格适合高密度扫描：粘性表头、细分隔线、状态标签、头像首字母、行动按钮。窄屏改为信息卡；表格、按钮、文案不得溢出或重叠。使用内嵌 SVG 线性图标和明确 tooltip/aria-label。
4. 所有风险颜色必须同时使用文字状态和图标/标签，不能只依赖颜色。表单用标签、帮助文字、必填标识、保存反馈；所有写入操作提示 toast。

六、验收标准
- 双击打开即可工作；断网下可完成 CRUD、搜索、提醒、CSV 与 JSON 备份恢复。
- 新建/编辑/删除、导入/导出、任务完成、谈话回访、预警解除、由预警新建帮扶、档案锁定流程均可实际操作，不得只是静态 UI。
- 刷新后数据、主题、导航偏好仍在；导入导出后字段不丢失；示例数据可完整清除。
- 使用脱敏中文示例数据覆盖全部模块，体现学生、任务、谈话、预警和重点档案间的联动。
- 对关键行为写最小化自动化或可运行的自检：本地存储读写、JSON 合并恢复、CSV 往返、学生合并、核心提醒规则与 CRUD。
先输出实现摘要和文件结构，然后完成代码。不要为了缩短工作量删减上述模块，也不要把敏感学生数据发送到任何服务。
```

## 分阶段提示词

### 1. 先搭基础骨架

```text
在现有项目中实现辅导员工作台的基础骨架：单文件 HTML、内联 CSS/JS/SVG、localStorage 存储层、window.CWB 扩展 API、全局状态与渲染器、浅深主题、桌面侧栏与移动端底栏、导航分组/折叠/置顶、顶部全局搜索、模态表单、toast、无障碍与示例数据。不要先做静态占位页；每一个壳层都要可交互并在刷新后保留偏好。
```

### 2. 建立工作主循环

```text
实现今日概览、工作任务、学生台账、谈心谈话与工作留痕五个核心模块，并串起工作闭环。首页按风险优先级汇总待办，任务可完成/顺延，谈话能安排回访，学生关注等级按 L1 7 天/L2 14 天/L3 30 天形成谈话提醒。首页增加 KPI、SVG 趋势与职责工作量；工作留痕从真实记录生成可编辑的小结。所有页面必须有搜索、筛选、CRUD、空状态、响应式列表。
```

### 3. 加入日常事务与专项台账

```text
在不破坏核心模块的前提下，加入校外住宿、假期去向、评优榜样、请销假、考勤、工作节点、学业预警、学业帮扶、奖助勤补。每个模块实现其完整业务字段、表单验证、列表查询和 CSV 模板/导入/导出。请销假逾期、工作节点临期、红色未解除预警必须进入首页待办；红色预警可一键标记解除或自动预填创建帮扶记录。
```

### 4. 加入重点关怀与资源中心

```text
新增重点学生档案、心理摸排、毕业生就业、政策智库、素材收藏、科创竞赛、模板库。重点档案使用首次设定/再次解锁的 4 位数字保护锁，并说明不是加密；一级跟踪中、重度未结案心理记录、临近竞赛截止分别进入首页高优先级提醒。政策与资源模块支持关键词与收藏，模板正文可一键复制，就业与奖助模块显示有业务含义的 KPI。
```

### 5. 完成数据可携与质量验收

```text
实现平台联动页和全部数据闭环：完整 JSON 交换包（学生按学号、其他按 id 的 merge/replace）、各模块带 UTF-8 BOM 的 CSV 往返、学生 Excel/CSV 表头映射与不覆盖旧值的合并、便携 HTML 导出、备份提醒和危险操作二次确认。补充可运行的自检或测试，至少覆盖 CRUD、学生合并、CSV 往返、JSON 恢复、提醒规则和主题持久化。逐项修复任何静态按钮、数据丢失、移动端溢出和无障碍缺口。
```

## 反推时不可丢失的产品原则

- 以“个人的当日工作判断”为中心，首页是操作台而不是报表墙。
- 本地优先与隐私最小化是架构要求；平台联动只能是显式导入/导出或用户授权后的预留能力。
- 记录必须能形成闭环：风险/学生 -> 谈话或措施 -> 回访/解除 -> 工作小结。
- 专项台账要服从统一的学生标识、职责分类、日期和状态约定，避免成为孤岛。
- 视觉要克制、专业、可长期使用，信息密度高但风险优先级必须一眼可见。

## 与原项目的取舍说明

本提示词保留了产品定位、19 个业务集合、数据联动和“低空学院·工程版”视觉规则，但没有要求复制原项目的私有内容、逐字文案或实现细节。若用于公开发布，应使用新的名称、图标、示例数据和截图，并在上线前按本校制度复核心理、资助、请销假等字段与流程。
