# 数据格式与联动约定

本文档定义辅导员工作台的本地数据格式、与重型「办公网站」平台的字段对照、交换包结构（v2），以及二次开发接口约定。目的是让本工作台未来能与平台**无缝联动**，且改造时可被 AI 可靠地理解和扩展。

---

## 1. 存储位置与命名空间

- 所有数据存于浏览器 `localStorage`；
- key 统一前缀：`cwb_v1_`；
- 数据以 JSON 字符串存储（写入时 `JSON.stringify`，读取时 `JSON.parse`）；
- 示例：

| key | 内容 | 版本 |
| --- | --- | --- |
| `cwb_v1_students` | 学生数组 | v1.0 |
| `cwb_v1_tasks` | 任务数组 | v1.0 |
| `cwb_v1_talks` | 谈话记录数组 | v1.0 |
| `cwb_v1_stay` | 校外住宿/走读数组 | v2.1 🆕 |
| `cwb_v1_leave` | 假期去向数组 | v2.1 🆕 |
| `cwb_v1_honor` | 评优榜样数组 | v2.1 🆕 |
| `cwb_v1_settings` | 设置（如辅导员姓名、是否初始化） | v1.0 |
| `cwb_v1_custom` | 自定义模块数据 | v1.0 |

> 单域名上限约 5MB，日常纯文本够用。不存图片等大文件。

## 4. 交换包 v2 结构（JSON）

`CWB.bridge.buildPackage(scope)` 产出（`PACKAGE_VERSION = 2`）：

```json
{
  "package": "counselor-desk",
  "package_version": 2,
  "app_version": "2.2.0",
  "exported_at": "2026-08-04T00:00:00Z",
  "counselor": {
    "name": "",
    "college_name": "",
    "org_code": ""
  },
  "scope": {},
  "students": [ { ... }, ... ],
  "tasks":    [ { ... }, ... ],
  "talks":    [ { ... }, ... ],
  "stay":     [ { ... }, ... ],
  "leave":    [ { ... }, ... ],
  "honor":    [ { ... }, ... ],
  "custom":   {},
  "stats": {
    "student_total": 0,
    "focus_total": 0,
    "crisis_total": 0,
    "task_total": 0,
    "task_done": 0,
    "talk_total": 0,
    "stay_total": 0,
    "leave_total": 0,
    "honor_total": 0,
    "by_duty": [
      { "duty":"ideology", "duty_name":"...", "tasks":0, "tasks_done":0, "talks":0 },
      ...
    ]
  }
}
```

### scope 参数

不传或传 `{}` → 导出全部数据。
可按范围过滤：
```js
bridge.buildPackage({ from:'2026-01-01', to:'2026-06-30' })  // 按日期范围
bridge.buildPackage({ students:false })                   // 排除学生数据
```

### 导入模式

`CWB.bridge.applyPackage(pkg, mode)`
- `'merge'`（推荐）：按 `id`（学生按 `student_number`）合并，已存在则覆盖字段，不存在则追加；
- `'replace'`：直接用包内数据覆盖本地（先规范化）。

> 导入会自动识别两种格式：本工作台导出的包（`pkg.package === 'counselor-desk'`）和通用格式（取 `pkg.data` 或 `pkg` 本身）。导入前会验证至少有一个非空数组。

平台侧只要能导出相同结构的 JSON，即可在本工作台「导入交换包」；反之亦然。

### 版本兼容

| PACKAGE_VERSION | 支持 |
| --- | --- |
| 1 | students / tasks / talks / custom |
| **2（当前）** | + stay / leave / honor + crisis_total / 各专项 total |

导入时会自动适配两个版本。

## 5. CSV 约定

- 导出的 CSV 带 **UTF-8 BOM**（`\uFEFF` 前缀），Excel 打开中文不乱码；
- 所有列表类视图均支持「导出 CSV」按钮；
- CSV 表头格式：`中文名(英文字段名)`，便于人工阅读和程序解析；
- 解析用 `CWB.utils.parseCSV`，兼容基础引号转义；
- 日期格式统一 `YYYY-MM-DD`；
- 学生导入支持中文表头自动映射（见 `CSV_MAP` 常量）。

### 各模块 CSV 表头

**学生台账**：`学号(student_number) / 姓名(full_name) / 性别(gender) / 班级(class_name) / 专业(major_name) / 年级(grade) / 学院(college_name) / 辅导员(counselor_name) / 学生当前状态(enrollment_status) / 政治面貌(politics) / 联系电话(phone) / 宿舍(dorm) / 关注等级(focus_level) / 关注类型(focus) / 备注(note)`

**工作任务**：`任务名称 / 职责分类 / 来源 / 涉及班级 / 截止日期 / 优先级 / 状态 / 备注 / 平台任务号`

**谈心谈话**：`日期 / 学号 / 姓名 / 方式 / 主题分类 / 谈话内容 / 问题研判 / 处理措施 / 需跟进 / 跟进日期 / 跟进完成`

**校外住宿**：`姓名 / 学号 / 年级专业 / 学生类型 / 申请理由 / 走读开始 / 走读结束 / 紧急联系人 / 紧急联系人电话 / 审批情况 / 备注`

**假期去向**：`姓名 / 学号 / 专业班级 / 家庭所在省市区 / 离校时间 / 返校时间 / 宿舍 / 本人手机号 / 是否延迟离校 / 留校缘由 / 指导老师 / 家长知情同意书 / 特殊情况备注`

**评优榜样**：`姓名 / 学号 / 申请类型 / 政治面貌 / 专业 / 班级 / 综合成绩专业排名 / 德育素质考核等级 / 入学来获奖学金情况 / 社会工作情况 / 其他获奖情况`

## 6. API 直连预留（未来）

`CWB.bridge` 已声明以下方法，当前为占位，实现 `request` 后可启用：

- `request(path, init)` —— 统一的网络请求封装（需自行实现 fetch + 鉴权 + 跨域处理）；
- `pullTasks()` —— 从平台拉取任务写入本地；
- `pushSummary(scope)` —— 把本地工作小结推送到平台。

> 安全边界：本地数据默认不外传。任何直连都需在用户明确授权下进行，且不得把含真实学生信息的备份文件未经脱敏提交到公开仓库。

## 7. 二次开发接口约定

- 新数据 key 一律 `cwb_v1_` 前缀；
- 新增实体字段改 `CWB.schema.*` 并在对应 `norm*()` 中补默认值的兼容处理；
- 自定义模块用 `CWB.modules.register(def)`，导航自动插入；
- 渲染用户输入前必须 `CWB.utils.esc()`，防 XSS；
- 不得引入外部 CDN / 框架 / 图表库（保持零依赖）；
- 不得 import 或依赖「办公网站」原项目代码（保持仓库隔离）；
- 新增业务模块建议参照本院真实台账文件校准字段命名（v2.1 的三个新模块即为范例）。
