# 数据格式与联动约定

本文档定义辅导员工作台的本地数据格式、与重型「办公网站」平台的字段对照、交换包结构，以及二次开发接口约定。目的是让本工作台未来能与平台**无缝联动**，且改造时可被 AI 可靠地理解和扩展。

---

## 1. 存储位置与命名空间

- 所有数据存于浏览器 `localStorage`；
- key 统一前缀：`cwb_v1_`；
- 数据以 JSON 字符串存储（写入时 `JSON.stringify`，读取时 `JSON.parse`）；
- 示例：

| key | 内容 |
| --- | --- |
| `cwb_v1_students` | 学生数组 |
| `cwb_v1_tasks` | 任务数组 |
| `cwb_v1_talks` | 谈话记录数组 |
| `cwb_v1_settings` | 设置（如辅导员姓名、是否初始化） |

> 单域名上限约 5MB，日常纯文本够用。不存图片等大文件。

## 2. 实体结构

### 2.1 学生 `student`

字段分**平台对齐字段**（与重型平台同名）与**本地扩展字段**。

| 字段 | 说明 | 类别 |
| --- | --- | --- |
| `student_number` | 学号 | platform |
| `full_name` | 姓名 | platform |
| `gender` | 性别 | platform |
| `class_name` | 班级 | platform |
| `major_name` | 专业 | platform |
| `grade` | 年级 | platform |
| `college_name` | 学院 | platform |
| `counselor_name` | 辅导员 | platform |
| `enrollment_status` | 在册状态 | platform |
| `phone` | 手机号 | local |
| `dorm` | 宿舍 | local |
| `focus` | 重点关注类型（见下） | local |
| `focus_level` | 关注等级 L1/L2/L3/空 | local |
| `note` | 备注 | local |

规范化函数：`CWB.norm.student(s)`。示例数据会被打 `_demo:true` 标记。

重点关注类型 `focus` 取值（来自 `FOCUS` 常量）：
`psych` 心理关注 / `study` 学业预警 / `econ` 经济困难 / `health` 身体状况 / `career` 就业困难 / `disc` 行为纪律 / `family` 家庭特殊。

### 2.2 任务 `task`

| 字段 | 说明 |
| --- | --- |
| `title` | 标题 |
| `duty` | 职责归属（九大职责代号之一） |
| `priority` | 优先级 P0/P1/P2 |
| `source` | 来源：学校下发/学院安排/平台下发/自主计划/学生诉求 |
| `due` | 截止日期 `YYYY-MM-DD` |
| `status` | 状态：todo/doing/done |
| `desc` | 说明 |
| `platform_ref` | 关联平台任务 ID（可选，联动用） |
| `follow_date` | 回访日期（可选） |

规范化函数：`CWB.norm.task(t)`。逾期判定：`daysFromToday(due) < 0 且 status != done`。

### 2.3 谈话 `talk`

| 字段 | 说明 |
| --- | --- |
| `date` | 谈话日期 |
| `student_name` | 学生姓名 |
| `duty` | 所属职责 |
| `way` | 方式：面谈/电话/线上/家访/集体 |
| `judge` | 研判结论 |
| `need_follow` | 是否需回访 |
| `done_follow` | 回访是否完成 |
| `next_date` | 下次谈话日期（由关注等级周期推算） |

规范化函数：`CWB.norm.talk(t)`。

## 3. 与平台字段对照

重型平台（办公网站）核心表与工作台对齐关系：

| 平台表 | 平台字段 | 工作台字段 | 对齐 |
| --- | --- | --- | --- |
| students | `student_number` | `student_number` | ✅ 同名 |
| students | `full_name` | `full_name` | ✅ 同名 |
| students | `gender` | `gender` | ✅ 同名 |
| students | `enrollment_status` | `enrollment_status` | ✅ 同名 |
| students | `graduation_cohort` | （预留） | 字段预留 |
| students | `student_type` | （预留） | 字段预留 |
| students | `active` | （预留） | 字段预留 |
| student_profiles | `class_name` | `class_name` | ✅ 同名 |
| student_profiles | `major_name` | `major_name` | ✅ 同名 |
| student_profiles | `grade` | `grade` | ✅ 同名 |
| student_profiles | `college_name` | `college_name` | ✅ 同名 |
| student_profiles | `counselor_name` | `counselor_name` | ✅ 同名 |
| student_profiles | `enrollment_month` | （预留） | 字段预留 |

> 前 8 个平台字段与工作台同名，导入导出零转换成本。`graduation_cohort` / `student_type` / `active` / `enrollment_month` 在平台侧存在，工作台已预留扩展位，后续如需对接可直接复用 `schema.student` 扩展。

## 4. 交换包（JSON）结构

`CWB.bridge.buildPackage('all')` 产出：

```json
{
  "app": "counselor-desk",
  "version": "1.0.0",
  "generatedAt": "2026-08-03T...",
  "scope": "all",
  "students": [ { ... }, ... ],
  "tasks":    [ { ... }, ... ],
  "talks":    [ { ... }, ... ]
}
```

导入：`CWB.bridge.applyPackage(pkg, 'merge' | 'replace')`
- `merge`：按 `id` 合并，已存在则覆盖，不存在则追加；
- `replace`：直接用包内数据覆盖本地（先规范化）。

平台侧只要能导出相同结构的 JSON，即可在本工作台「导入交换包」；反之亦然。

---

## 5. CSV 约定

- 导出的 CSV 带 **UTF-8 BOM**（`\uFEFF` 前缀），Excel 打开中文不乱码；
- 列表类视图（如学生花名册）支持「导出 CSV」；
- 解析用 `CWB.utils.parseCSV`，兼容基础引号转义；
- 日期格式统一 `YYYY-MM-DD`。

---

## 6. API 直连预留（未来）

`CWB.bridge` 已声明以下方法，当前为占位，实现 `request` 后可启用：

- `request(opts)` —— 统一的网络请求封装（需自行实现 fetch + 鉴权 + 跨域处理）；
- `pullTasks()` —— 从平台拉取任务写入本地；
- `pushSummary()` —— 把本地工作小结推送到平台。

> 安全边界：本地数据默认不外传。任何直连都需在用户明确授权下进行，且不得把含真实学生信息的备份文件未经脱敏提交到公开仓库。

---

## 7. 二次开发接口约定

- 新数据 key 一律 `cwb_v1_` 前缀；
- 新增实体字段改 `CWB.schema.*` 并在 `norm*` 中补默认值的兼容处理；
- 自定义模块用 `CWB.modules.register(def)`，导航自动插入；
- 渲染用户输入前必须 `CWB.utils.esc()`，防 XSS；
- 不得引入外部 CDN / 框架 / 图表库（保持零依赖）；
- 不得 import 或依赖「办公网站」原项目代码（保持仓库隔离）。
